Latch 5.1.0 Remote desktop over Tailscale Release notes ↗

Your machines,
on any of your machines.

Latch streams a whole desktop, full screen, over your own Tailscale network. Mac, Windows, Linux and a VPS container run the same app: each one lists the others, and each one can share its own desktop.

Download 5.1.0 ↓ Source on GitHub ↗

01Session

Open Latch. Click Connect. The desktop appears.

Every install lists every other machine on your Tailscale account and can open its desktop. There is no host or client role to choose.

  1. Step 1

    Set up sharing.

    On the computer you want to reach, open the Sharing tab. On Windows, Set up as administrator takes one administrator prompt: it opens Latch’s port to your tailnet only, turns Fast Startup off and arms the network card for Wake-on-LAN. A Mac asks for Screen Recording and Accessibility once. The streaming engine is part of Latch; there is nothing else to install.

  2. Step 2

    Connect. Nothing to pair.

    Tailscale already knows who you are. The other machine checks your identity with tailscale whois, so there is no PIN to type and no certificate to accept. If a Windows PC is asleep, Latch wakes it and waits.

  3. Step 3

    The desktop, and nothing else.

    Full screen by default. Click the picture and the mouse is captured, as in a game, so games that read raw mouse movement work. Ctrl+Alt (Control-Option on a Mac) is the host key, as in a hypervisor: it frees the mouse and drops this toolbar over the picture. The text clipboard follows you both ways.

02Network

Tailscale is the path and the identity check.

A machine answers only peers signed in to the same Tailscale account. There is no Latch account or password, and the control port is open to your tailnet only.

Control port
TCP and UDP 47850. It answers loopback and Tailscale addresses that tailscale whois puts on your account. Everyone else gets a 403.
Stream
Latch’s own stream protocol over UDP, inside WireGuard, with Reed-Solomon forward error correction. A lost packet is rebuilt, not waited for.
Firewall
Windows setup opens port 47850, TCP and UDP, to 100.64.0.0/10, Tailscale’s address range, and nothing else.
Accounts
None. No Latch account, no password, no pairing. Your Tailscale sign-in is the only one.
Wake
Wake-on-LAN from the PC’s own network, or from anywhere if its router forwards UDP 9. Test wake tells you which applies.
Power
Sleep, restart and shut down from another machine. The PC can switch remote power actions off.

03Specifications

What Latch asks the other machine for.

These are the settings Latch 5.1.0 offers, not benchmarks. What you get depends on both machines and the path between them.

Resolution

Match screen, this display’s own pixel size, by default.

  • 540p 960 × 540
  • 720p 1280 × 720
  • 900p 1600 × 900
  • 1080p 1920 × 1080
  • 1440p 2560 × 1440
  • 4K 3840 × 2160

The sharing machine’s desktop follows the size asked for, and goes back when you disconnect.

Frame rate

30, 60, 90, 120, 144, 165 or 240 fps. 60 by default.

Above 60 needs a display on the sharing machine that runs that fast.

Bitrate

2 to 150 Mbps. The encoder aims at it while the picture moves; a still screen uses less.

50 Mbps by default, on every path.

Quality
  • Recommended Match screen · 50 Mbps
  • Smooth 1080p · 60 fps · 20 Mbps
  • Balanced Match screen · 60 fps · 50 Mbps
  • Sharp Match screen · 60 fps · 100 Mbps

Custom sets all three yourself.

Codec

HEVC between two Macs, H.264 everywhere else. Either can be forced.

Decoding
  • macOS VideoToolbox, hardware, HEVC and H.264
  • Windows Media Foundation, hardware when the GPU has it, H.264
  • Linux Latch’s own decoder, software, H.264
Encoding

Built into Latch on the sharing machine: VideoToolbox on a Mac, the GPU’s encoder through Media Foundation on Windows, Latch’s own H.264 encoder on Linux and a VPS with no GPU.

Audio

Lossless, 48 kHz stereo, played on this machine’s default output.

Input

Captured mouse with raw movement, or free. ⌘ acts as Ctrl on a PC by default.

Clipboard

Text, both ways, up to 32 KB.

Transport

Tailscale (WireGuard): direct, your own peer relay, or DERP.

1200-byte datagrams, sized for the tunnel’s 1280-byte MTU.

Updates

The Mac app checks GitHub about every six hours, verifies the SHA-256 and code signature, and installs when no stream is running.

It sends new Latch Host builds to Windows PCs over port 47850.

Built with

Rust, top to bottom: the streaming engine, the protocol and the H.264 codec are Latch’s own. No C or C++.

GPL-3.0-or-later.

macOS

Apple Silicon · macOS 13+

In Terminal. Downloads the latest release, checks its SHA-256 and signature, installs it in Applications and opens it.

Terminal 
curl -fsSL https://raw.githubusercontent.com/MrBeldum/latch/main/scripts/install-macos-release.sh | bash

Downloaded the archive in a browser instead? The app is ad-hoc signed, so unpack it and clear the quarantine flag first: xattr -dr com.apple.quarantine Latch.app

Download for macOS ↓ latch-macos-arm64.tar.gz

Windows

x64 · Windows 10 1809+

  1. Unzip, then run latch-host.exe, or install-host.ps1 for shortcuts and start at logon.
  2. Open the Sharing tab and click Set up as administrator. One administrator prompt opens the port to your tailnet and readies Wake-on-LAN.
Download for Windows ↓ latch-windows-x64.zip

Docker

Linux VPS · arm64, amd64

Put a Tailscale auth key and a hostname in .env, then start the container.

Shell 
git clone https://github.com/MrBeldum/latch
cd latch
cp deploy/node/env.example deploy/node/.env
# paste a Tailscale auth key, pick TS_HOSTNAME
docker compose -f deploy/node/docker-compose.yml up -d --build

Linux

x64, arm64 · glibc 2.39+

latch-host for an X11 desktop, run under systemd, with a .sha256 beside each archive. Or build it from source: Latch needs nothing but Rust.
